디스크립션

목적: 핸드오프 때 개발자(와 개발자가 쓰는 AI)가 화면 내용을 빨리 파악하는 것. 시안은 항상 디자인 시스템 + 디스크립션 한 묶음이에요.

원칙: 짧게, 핵심만

  • 필요한 건 꼭 넣고, 불필요한 건 넣지 않아요. 길면 핵심을 놓쳐요.
  • 한 줄 = 한 대상 + 조건 → 결과. 한 줄은 대략 15~40자.
  • 화면 하나에 라벨 1~4개, 라벨마다 1~3줄이 보통이에요. 더 길어지면 줄일 수 있는지 먼저 봐요.
  • 문장이 아니라 메모처럼 써요: "선택 시 시트 닫힘", "1초 노출 후 사라짐", "최대 100자".
  • 지시 대상(버튼명·영역명)은 화면에 보이는 이름 그대로 써요.
  • 본문은 줄마다 글머리 기호(•) 목록으로 써요. 라벨(A/B/공통)은 목록이 아니에요.

꼭 넣을 것

종류 예시
동작 (누르면 무엇이 되나) "선택 시 레슨으로 진입" · "마이크 버튼 선택 시 일시정지"
노출 조건 (누구에게, 언제) "이벤트 기간 중 앱 진입 시 최초 1회 노출" · "대상: 한국어 코스 유저"
예외 "가장 앞 유닛일 경우 좌측 버튼 미노출" · "공백만 입력 시에도 비활성"
시간·횟수 "페이지 진입 시 1초간 노출 후 사라짐" · "정답일 시 1초 딜레이 뒤 사라짐"
제한값 "최대 100자" · "영문만 입력 가능"
상태 변화 "음성 재생 중에는 마이크 비활성화"
터치 영역 "터치 영역: 스크린 전체"

이유는 필요할 때만 짧게

이유가 있어야 오해가 없거나, 나중에 "왜 이렇게 했지?"를 찾게 될 결정에만 남겨요. 한 줄, 결과 앞이나 괄호 안에 써요.

  • 남길 때: 일반적인 방식과 다르게 한 것, 바꾸면 안 되는 것, 정책·실험 때문에 정한 것, 예전 결정을 바꾼 것
    • "결제 후 돌아온 유저라 결제한 플랜만 노출"
    • "브랜드 민트로 바꾸지 않음 (밝은 민트는 의도된 색)"
    • "26.08 변경: 문구 축약 (버튼 폭 부족)"
  • 남기지 않을 때: 화면만 봐도 알 수 있는 것, 일반적인 동작 ("뒤로가기 선택 시 이전 화면")

넣지 않을 것

빼는 것 나쁜 예 고친 예
필요 없는 이유 설명 "유저가 이미 결제를 하고 돌아온 케이스이기 때문에 … 인지시켜 줌"을 길게 "결제 후 돌아온 유저라 결제한 플랜만 노출"
내부 메모 "정책 정의 하는 중" · "(논의 중)" 빼고 채팅으로 공유
부탁하는 말투 "같이 닫히게끔 해주시면 됩니다!" "얼럿 닫히면 창도 함께 닫힘"
개발 용어·저장 방식 "저장: iOS Keychain / AOS SharedPreferences" "앱 삭제 후 재설치해도 iOS는 표시"
계산 로직 풀어쓰기 복습 단어 고르는 방법을 한 문단으로 화면에 보이는 결과만 한 줄, 로직은 기획서 링크
같은 문장 반복 라벨 A와 C에 같은 문장 공통 라벨에 한 번만
번역 문구 목록 디스크립션 안에 ko/en/ja 문구 나열 번역 섹션에 화면으로
정보 없는 문장 "기존과 동일" · "타이틀 텍스트" 빼기

꼭 필요한 어려운 단어가 있으면 그대로 쓰고, 맨 아래 "용어" 항목에 한 줄 설명을 붙여요.

배치

  • 화면마다 바로 아래에 달아요. 화면 하단 +40, 같은 x, 폭 = 화면 폭. 여러 화면 밑에 하나로 모으지 않아요.
  • 자리가 없으면 프레임을 옮기고 섹션을 늘려서라도 자리를 만들어요. 겹침·가림은 어떤 경우에도 안 돼요.
  • 화면의 영역 표기 라벨 ↔ 바로 아래 디스크립션 라벨이 한눈에 짝지어져야 해요. 라벨은 화면마다 A부터 다시 시작해도 돼요.

모양 (guide 페이지 기준)

요소 모양
디스크립션 박스 파랑 (122,163,255) 80%, Corner Radius 2, 세로 오토레이아웃 패딩 20 · 간격 10. 라벨 Noto Sans Black 24 흰색 + 설명 Noto Sans Medium 18 흰색
영역 바 (기본) 파랑 90%, Corner Radius 없음. 폭 40 + 라벨 Bold 24 (또는 폭 60 + Bold 32). 높이 = 가리키는 영역 높이 (최소 40). 화면 바깥 10 띄워서: 왼쪽 요소는 화면 왼쪽, 오른쪽 요소는 화면 오른쪽
뱃지 (예외) 40×40 원형 파랑 100%, 흰색 Bold 24, 화면 안. 영역이 작거나 묶음 안 하나를 콕 집을 때만
플로우 헤더 파랑 Corner Radius 10, 높이 80, 흰색 Inter Black 30 가운데, "{화면} > {플로우}"
변경 표시 / 참고 빨강 = 기획 후 바뀐 부분, 회색 = 참고

헤더 바 구조

바 안 글자는 항상 가로·세로 가운데예요.

단계 모양 예
1. 콘텐츠·기능 묶음 흰색 바, 높이 80, Corner Radius 10, 검정 Inter Black 30, 묶음 전체 폭 온보딩 플로우, 보캡
2. 플로우·비교·하위 유형 높이 80, Corner Radius 10, 흰색 Inter Black 30. 기존 = 회색 (193,198,211), 추가·변경 = 파랑 80% 기존 플로우 / 추가, AS-IS / TO-BE
3. 단계 라벨 (필요할 때) 회색 박스 375×131, 흰색 Noto Sans SemiBold 64 계정생성, 가입완료

간격

  • 헤더 바 ↔ 아래 헤더 바: 80
  • 헤더 바 ↔ 화면: 70~80 (글자·바와 화면 사이는 최소 40)
  • 화면 사이: 120 이상 (양쪽 영역 바가 겹치지 않게)
  • 화면 위에 섹션 제목·부제 같은 설명용 글자를 따로 쓰지 않아요. 헤더 바 구조로 보여줘요.

그림 주석 (크기 · 마진 · 터치 영역)

글로 쓰면 길어지는 건 그림으로 표시해요. 화면 위에 바로 그리지 않고, 그 부품이 처음 나오는 화면 옆에 부품을 떼어 놓고 설명해요. 그림으로 표시했으면 디스크립션에 같은 내용을 다시 쓰지 않아요.

표시할 것 방법
케이스별 크기 (최소 / 두 줄 / 최대) 파랑 헤더 바에 케이스 이름 → 아래에 부품을 떼어서 배치
마진 · 간격 요소 사이에 빨강 (255,122,122) 80% 막대 (높이 = 간격 값) + 오른쪽에 흰색 Bold 16 "8px"
안쪽 여백 가장자리에 반투명 파랑 막대 + 바깥에 "16px" 라벨, 아래 흰색 불릿으로 규칙
위치 기준 메모 짧은 흰색 글자 ("센터 기준 60px 위로")
안 보이지만 자리를 차지하는 영역 (애니메이션·로티) 화면 옆에 세로 막대 (파랑, 배경 애니메이션은 회색) + 세로 글씨로 이름
터치 영역 · 이미지 영역 부품을 어두운 패널 (57,57,66, Corner Radius 20)에 떼어 놓고 양방향 화살표 + 빨강 계열 라벨

값(px)은 실제 디자인을 재서 써요. 추측하지 않아요.

모범 페이지에서도 따라 하지 않을 것: "정책 정의 하는 중", "(논의 중)" 같은 메모, 같은 문장 반복, 로직 한 문단 설명.

다 쓰고 나서 확인

  • 화면마다 바로 아래에 있나
  • 영역 표기 라벨과 디스크립션 라벨이 짝지어지나
  • 줄마다 조건 → 결과인가, 한 줄에 대상이 하나인가
  • 시간·예외·제한값이 빠지지 않았나
  • 필요 없는 이유 설명, 메모, 부탁하는 말투, 개발 용어, 반복 문장이 없나 (남긴 이유는 한 줄인가)
  • 더 줄일 수 있는 줄이 없나
틀린 내용이 있거나 필요한 부품·토큰이 없으면 디자인 시스템 담당자에게 알려 주세요. 사이트와 피그마가 다르면 피그마가 기준이에요.
